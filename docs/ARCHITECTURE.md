# 项目架构

## 一句话

AI 视频大师Agent = `案例雷达` + `能力沉淀` + `技能路由` + `执行层接口`

## 四层结构

### 1. Radar Layer

输入：公开案例、官方教程、changelog、方法页。

输出：

- 结构化案例记录
- 证据边界
- 候选能力

对应目录：

- `knowledge_base/cases/`
- `reports/weekly/`

### 2. Knowledge Layer

输入：经过筛选的高质量案例。

输出：

- 能力定义
- 适用阶段
- 规则模板

对应目录：

- `knowledge_base/abilities/`
- `knowledge_base/schemas/`

### 3. Skill Layer

输入：生产需求或研究需求。

输出：

- 路由规则
- 操作顺序
- 升级/观察/跳过判定

对应目录：

- `skills/`

### 4. Execution Interface Layer

输入：已确认的能力与规则。

输出：

- 交给 `ai-video-supervisor` 的生产策略
- 交给外部模型/工具链的输入要求

当前不在本仓库直接执行图像或视频生成。

## 核心原则

### 原则 1：知识库优先于灵感堆积

一个案例只有在以下条件满足时才值得留在主知识库：

- 来源公开可读
- 方法透明
- 能抽出可复用结构
- 能说明适用阶段

### 原则 2：能力先小后大

能力条目优先沉淀“最小可复用规则”，不要一上来就固化成庞大工作流。

例如：

- `声音锚点配置锁`
- `控件先于提示词`
- `领域词汇提示法`

这些都比“完整视频流水线大全”更容易验证。

### 原则 3：Notion 不是唯一真相源

Notion 是协作数据库，不应成为唯一知识底座。

本地仓库必须保留：

- 知识结构
- seed 数据
- 周报历史
- 同步合同

### 原则 4：执行层和知识层分离

`ai-video-master-agent` 不直接宣称“已生成视频”。

真正的生成、重试、交付状态，应由 `ai-video-supervisor` 或其他执行链条负责。
