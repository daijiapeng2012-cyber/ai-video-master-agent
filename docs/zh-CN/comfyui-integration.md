# ComfyUI 集成

ComfyUI 是目前非常强的开源执行环境之一，尤其适合 AI 图像和视频工作流。

这个仓库不打算替代 ComfyUI，而是想把“送进 ComfyUI 之前的知识、规则和路由”做扎实。

## 职责分工

### 这个仓库负责

- 收集公开工作流证据
- 结构化沉淀能力
- 定义路由逻辑
- 导出可交接的 handoff 包
- 生成每周公开更新

### ComfyUI 负责

- 真正的节点图执行
- 本地或远程推理编排
- 图像/视频生成与转换
- checkpoint / LoRA / control asset 接线

## 为什么这样拆更合理

ComfyUI 很强，但节点图本身并不能解决这些问题：

- 这个工作流值不值得存在
- 某个模式是否已经稳定到可复用
- 案例和长期能力如何区分
- 如何保留持续周更的研究轨迹
- 如何保存来源证据和方法边界

这个仓库补的就是这些部分。

## handoff 方式

推荐桥接方式：

1. 本地先整理案例和能力
2. 再把目标需求映射到一组可复用能力
3. 导出紧凑的 handoff 包
4. 由 ComfyUI 执行者或下游执行层把 handoff 包映射进节点图

## handoff 包

运行：

```bash
python3 scripts/export_comfyui_handoff.py --output examples/comfyui_handoff.sample.json
```

导出内容包括：

- 仓库元信息
- 被选中的能力
- 关联案例
- 阶段覆盖
- 生成约束
- review 备注

它应该保持小、清楚、可检查，而不是直接把节点图塞进知识仓库。

## 实践建议

- ComfyUI 专属节点图逻辑放在执行层
- 可复用方法规则留在知识库
- 节点图和运行时接线由执行仓库维护
- 证据、能力命名和周报总结由本仓库维护
